# SCSP Localify full-functionality acceptance for SCSP 2.17

Reviewed: 2026-09-15.

This file owns the compatibility and acceptance matrix for the full SCSP Localify plugin on SCSP 2.17. It is separate from the already accepted `SCSP-Localify-Lite` target.

## Architecture

- The offline profile exposes one extension slot as `scsp_localify_plugin.dll`.
- The accepted package currently fills that slot with Lite. Full may replace it only after preserving every accepted localization/runtime regression gate.
- Normal full builds do not define `__TOOL_HOOK_NETWORKING__`; the generated 1,064 protobuf types / 2,128 request-response hooks are developer instrumentation, not production functionality.
- Current full `DllMain` hard-gates initialization to `imasscprism.exe`; `UnityCrashHandler64.exe` and other hosts return before config/hook worker setup.

- `3DResolutionScale` no longer depends on `RenderManager.GetResolutionSize` for normal MV rendering. SCSP 2.17's active owner is URP `UniversalRenderPipelineAsset.renderScale`; the plugin hooks the setter, preserves the game's requested base scale, multiplies by the configured value, clamps to URP's `0.1..2.0` range, and provides getter readback.

Runtime readback values remain directly visible because they are state, not tips.

## Deprecated / non-production paths

- `allowUseTryOnCostume` still parses from config, but its original LiveCostumeChangeView hooks are inside `__OBSOLETE_HOOK__` and are not production support.
- The **old** `g_unlock_all_dress` / `g_unlock_all_headwear` implementation depended on GetDress/GetHairstyle/GetAccessory and reply/dictionary hooks inside `__OBSOLETE_HOOK__`. `unlockAllDress` has now been migrated to the current 2.17 `CostumeChangeViewModel` ctor + `CostumeStatusExtensions.CanWear(3)` path; `unlockAllHeadwear` remains deprecated/unimplemented on a current owner path.
- old Live depth-of-field/update hooks and old LiveCostumeChangeModel/View hooks are commented/obsolete.
- current maintained costume work is the newer `CostumeChangeViewModel` path; obsolete config/UI wording must be removed or mapped to a validated current implementation rather than silently doing nothing.

## Native ownership conflicts

Accepted offline logs already show another native owner for `StoryExtensions.IsLocked`, `CostumeChangeViewModel.ctor`, `CostumeChangeViewModel.CanDecide()` / `CanDecide(part)`, and `CostumeStatusExtensions.CanWear`. The full-candidate architecture therefore uses **single-owner profiles**, never double-hook composition. `build-full-localify-candidate.ps1` has four hard-gated modes: `SafeSmoke` disables both overlapping full behaviors, `FullStoryOnly` enables only the full story owner, `FullDressOnly` enables only the migrated full dress owner, and `FullOwnerParity` enables both. Every mode writes `scsp-unlock.json` with `unlockStories=false / unlockDress=false`, so the offline Story/Costume owners are never composed with the full plugin. All modes hard-fail if their ownership invariants are violated. Auto-apply, same-idol, costume save/replace, free camera and other higher-risk features remain off in both baseline package profiles until their own runtime rows are accepted. On final deterministic `A4739B73...E9A5E`, SafeSmoke and FullOwnerParity rebuild to 5,567-file packages with `unexpected_drift=0`; FullOwnerParity verifies offline story/dress ownership disabled and full-plugin story/dress ownership enabled, and a bounded 30-second parity startup smoke survives/responds with exact overlay restore. `FullDressOnly` and `FullStoryOnly` are the narrower ownership modes used by manual groups D and G respectively.

## Build problem

The historical full target uses Conan for Boost, cpprestsdk, minizip/zlib, msgpack, sqlite and nlohmann-json, but actual source use is much narrower:

- nlohmann-json: JSON serialization/helpers
- Boost: one base64 decode
- cpprest: UTF conversions plus one asset HTTP download
- minizip: header included, no active unzip calls found
- sqlite/msgpack: no active source use found

The 2.17 full target is deterministic on the same local MSVC/Premake toolchain as Lite/Probe. `premake-full-2.17.lua` builds MinHook locally and links only Windows SDK libraries (`d3d11`, `dxgi`, `dwmapi`, `psapi`, `urlmon`, `crypt32`) plus vendored headers. Boost base64 was replaced with `CryptStringToBinaryA`, cpprest UTF conversion with Win32 UTF conversion helpers, cpprest HTTP download with `URLDownloadToFileW`, and unused minizip/cpprest-listener includes were removed. The remaining vendored nlohmann headers carry their MIT license. The full target intentionally omits `MultiProcessorCompile`: isolated `/MP` clean builds exposed byte-different but semantically equivalent `.text`. Final frozen s6 source now passes two isolated no-`/MP` clean builds byte-identically at **1,398,272 bytes / SHA-256 `A4739B732AF380F7524629E8C04FEF762EF0B142D32EC1307AFE6D6276CE9A5E`**. During the same regression pass, the permanent localization verifier was corrected to accept TranslationData descendants of source anchor `703eef6` while reconstructing inferred-new-2.17 source values from that pinned commit rather than the translated checkout. Current accepted TranslationData `1a2ba93` passes the exact localizetext gate at `5631` tables / `138036` rows / `138036` mapped / `0` actionable; final blocker validation is 365/365 / 39,949 rows / 0 failures / 0 warnings.
